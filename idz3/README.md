## Сборка и запуск

Требуются Linux, компилятор C (например, GCC), make и поддержка POSIX shared memory, семафоров и очередей сообщений. Для тестов нужен Python 3. Для очередей максимальный размер сообщения системы (`/proc/sys/fs/mqueue/msgsize_max`) должен быть не меньше 8192 байт; на некоторых системах также может потребоваться увеличить лимит числа очередей.

```sh
make
./tanks_unnamed --batch --plain --seed 1 --delay 0 --max-ticks 10
./tanks_named --batch --plain --seed 1 --delay 0 --max-ticks 10
```

Оба варианта создают работников через `fork()` и передают данные через POSIX shared memory. Первый использует неименованные семафоры в разделяемой памяти, второй — именованные.

Независимые процессы запускаются в двух оболочках. В первой запустите одну из команд:

```sh
./tanks_independent --batch --plain --seed 1 --delay 0 --max-ticks 10
# или
./tanks_queue --batch --plain --seed 1 --delay 0 --max-ticks 10
```

Арбитр напечатает команды `./tanks_worker ...`. Скопируйте **все** эти строки во вторую оболочку, добавив к каждой ` &`, и выполните их сразу. Арбитр ожидает готовности каждого работника до 30 секунд. Так все работники запустятся одновременно в одной оболочке; после запуска можно ввести `wait`, чтобы дождаться их завершения. Не копируйте команду `wait` в числе команд работников. Первый вариант использует разделяемую память и именованные семафоры, второй — очереди сообщений и именованные семафоры. Уникальное имя сессии передаётся в напечатанных командах; его нужно сохранить без изменений.

Без параметров программа предлагает интерактивную настройку. `--help` показывает все параметры и диапазоны. `--log FILE` задаёт путь журнала, `--no-focus` отключает фокус координаторов, `--max-ticks 0` убирает ограничение тактов. `Ctrl+C` прерывает бой. Проверки: `make test`.
